# 中小企业应收账款融资 DApp 移动端用户操作手册

> 适用：Sepolia 教学原型设计　|　界面语言：English　|　钱包：MetaMask　|　结算资产：Sepolia 测试 ETH

## 1. 使用前准备

在手机安装 MetaMask，为 Funder 和 Buyer 准备足够的 Sepolia 测试 ETH，以支付放款/还款金额及额外 Gas。测试 ETH 不具有真实美元价值。请从项目提供的正式演示 URL 打开 DApp，确认页面显示 `Sepolia`、正确的钱包地址和公布的合约地址。不要在网页中输入 MetaMask 助记词或私钥。

演示人员应预先核对 Funder 的测试 ETH 余额高于本金 `P` 加预计 Gas，Buyer 的余额高于票面金额 `V` 加预计 Gas。项目不需要部署 MockUSD 或执行代币授权；放款与还款各是一笔携带 ETH 的钱包交易。

优先在 MetaMask 移动端浏览器打开页面。首次登录需签署一次性登录消息。登录签名本身不转账，后续业务交易仍需逐笔在钱包中确认。若切换钱包地址或网络，重新连接和登录。本文用中文解释步骤，所引用的页面名称和提示均为实际英文界面文案。

## 2. 角色开通

打开 `Profile → Role Application`，选择 Supplier、Buyer、Funder、Arbitrator 或 Auditor，填写申请资料并提交。随后按提示签署链上 `requestRole`。状态依次显示 `Application received`、`On-chain request confirmed` 和 `Awaiting Admin approval`。Admin 通过并签署 `approveRole`，且交易被索引后，角色才生效。一个钱包可以有多个角色；`Home` 顶栏可切换当前工作视图。每笔业务仍需满足不同参与方地址和利益冲突规则。

## 3. Supplier 正常流程

1. **登记发票**：进入 `Activity → Invoices → New Invoice`，填写 Buyer 钱包地址、发票号、票面金额、签发日和到期日，上传发票及必要材料。检查文件哈希和摘要，再用 MetaMask 签署 `submitInvoice`。页面显示交易哈希与确认状态。
2. **等待 Buyer 确认**：发票为 `PendingConfirmation`。Buyer 确认后变为 `Confirmed` 并产生不可转让 Invoice NFT；若 Buyer 拒绝，发票为 `Rejected` 终态。
3. **发起融资**：在已确认发票详情输入本金 `P`、可接受最高年化利率、融资截止时间和 Holdback 比例，确认后签署 `openFinancing`。
4. **比较报价**：在融资详情查看各 Funder 的年化利率、预计利息和有效状态。选中一个报价并签署 `acceptOffer`。被选中 Funder 有 24 小时放款；选中不代表已经到账。
5. **查看收款**：放款链上确认后，在详情查看 `SupplierUpfront = P-R`、暂扣 Holdback `R`、到期日和锁定利息。Buyer 正常还款后查看最终尾款与结算记录。

在接受报价前可取消本轮融资。融资截止无人被选中时本轮申请过期，发票回到可再次发起融资的 `Confirmed`。若 Funder 放款超时，按页面状态等待报价过期处理；申请仍有效时可以选择其他活跃报价。

## 4. Buyer 正常流程

在 `Home → Pending Review` 打开指定发票，核对 Supplier、发票号码、票面金额、日期及文件材料。只有确实认可该应付款时才签署 `confirmInvoice`；否则选择 `Reject Invoice` 并签署 `rejectInvoice`。确认后核心字段不可修改。

在 `Home → Repayments Due` 打开已放款发票。还款金额为票面金额 `V`（测试 ETH），先检查钱包余额是否足以支付 `V` 和预计 Gas，再签署携带 `V` 的 `repayInvoice`。正常情况下，还款交易同时完成分账；如果存在争议，资金先留在合约并进入 `RepaymentDeposited`，等待裁决后结算。此状态不要再次还款。

## 5. Funder 正常流程

在 `Activity → Available Requests` 查看已确认发票与融资条件，核对本金、最高利率、融资截止日、Buyer 与 Supplier 地址。提交利率报价并签署 `submitOffer`。报价被接受前可以撤回；被选中后在 24 小时内进入 `Funding Due`。

放款前核对 Sepolia 测试 ETH 余额、需要转入的本金、额外 Gas、Supplier 首笔到账和 Holdback。签署携带完整本金 `P` 的 `fundFinancing`；只允许被选中的 Funder 一次性放足本金。放款成功后查看预计利息、还款状态；若 Buyer 最终违约，查看返还的 Holdback、本金损失和未付利息记录。

## 6. 争议、裁决与审计

Supplier、Buyer 或本次融资的 Funder 可在符合条件的非终态发票上发起争议。进入 `Invoice Details → Dispute`，选择类型、上传证据文件，核对哈希后签署 `openDispute` 或 `submitEvidenceHash`。争议状态与发票状态分别显示；冻结期间按页面提示执行合约允许的动作。

Arbitrator 在 `Activity → Pending Disputes` 查看阶段、参与方、链上证据哈希和有权访问的链下材料，只能选择页面列出的预定义裁决。`RESUME` 恢复流程，`CANCEL` 只用于放款前取消本轮融资，`CONFIRM_DEFAULT` 只在允许阶段确认违约。裁决前再次核对资金后果。

Auditor 打开 `Activity → Audit Dashboard` 查看汇总、状态分布、交易历史和单张发票时间线。点击交易哈希可到区块浏览器核对区块、发送者与事件。Auditor 没有业务写操作。

## 7. 交易状态和常见问题

| 英文页面提示 | 含义 | 建议操作 |
|---|---|---|
| `Awaiting Wallet Signature` | 钱包尚未批准操作 | 回到 MetaMask 检查网络、地址、金额和合约 |
| `Submitted / Confirming` | 已取得 txHash，等待 Sepolia 确认 | 保留 txHash；不要因页面未刷新就重复发起资金交易 |
| `Transaction confirmed. Syncing data…` | 交易已成功，后端索引尚未更新 | 使用 `Retry Sync` 或稍后刷新；可用区块浏览器核对 |
| `Signature cancelled` | 钱包拒绝请求，未广播交易 | 如仍需执行，在页面重新发起 |
| `Switch to Sepolia` | 当前不是 Sepolia | 切换至 chainId `11155111` 后重试 |
| `Insufficient balance` | 钱包的 Sepolia 测试 ETH 不足以支付交易金额与 Gas | 补足测试 ETH 后重试 |
| `Incorrect ETH amount` | 钱包交易附带的 ETH 与 `P` 或 `V` 不符 | 刷新页面并按最新金额重新提交 |
| `Offer or request expired` | 当前状态不允许继续操作 | 刷新详情，按最新状态重新报价或申请 |
| `Transaction reverted` | 合约拒绝该操作 | 查看页面原因、权限与状态；保留 txHash 用于排查 |

本手册描述目标交互；最终提交时应根据已部署页面、实际合约地址、Sepolia 测试 ETH 获取方式和截图更新。业务规则和资金公式见[总体设计文档](设计文档.md)，页面说明见[UI 设计文档](UI设计文档.md)。
