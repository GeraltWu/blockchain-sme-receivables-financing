# SME Receivables Financing DApp 用户操作手册

> 适用于当前 Sepolia 演示版本。界面语言为 English，所有资金均为 Sepolia test ETH。

## 1. 使用前准备

1. 准备 MetaMask，并切换到 Sepolia（chain ID `11155111`）。
2. Funder 钱包需要足够的测试 ETH 支付本金和 Gas；Buyer 钱包需要足够的测试 ETH 支付发票面值和 Gas。
3. 打开 DApp 后点击连接钱包，检查页面显示的钱包地址和网络。
4. 不要在网页中输入助记词或私钥。

连接钱包用于链上读写；`Sign in` 是后端签名登录。演示业务交易不要求每一步重新登录，但以下内容依赖登录：

- 创建发票时保存 `Invoice number` 等链下元数据；
- 有权限的用户读取发票编号；
- 查看后端保存的已验证交易记录。

切换钱包后登录状态会清除。如发现发票编号不可见，用当前钱包重新登录并刷新数据。

## 2. 角色与界面

顶部角色列表中的绿点表示该角色已激活，红点表示未激活。同一钱包可以拥有多个角色。

申请角色：进入 `Profile → Manage`，选择角色并点击 `Request role`，在 MetaMask 确认交易。Admin 随后进入同一页面，在 `Pending requests` 中点击 `Approve`。

底部主导航为：

- `Home`：当前角色摘要和待办；
- `Activity`：发票、融资、争议或审计业务；
- `Transactions`：交易状态和区块浏览器入口；
- `Profile`：钱包、网络、登录和角色管理。

## 3. Supplier 操作

### 3.1 创建发票

1. 用 Supplier 钱包连接并 `Sign in`。
2. 进入 `Activity → Invoices`，点击 `Create invoice`。
3. 填写 Buyer wallet、Invoice number、Face value、Issue date、Due date。
4. `Document hash` 可留空，前端会生成演示用哈希。
5. 提交并在 MetaMask 确认。

页面先创建链上发票，再把编号绑定到链上 invoice ID。当前系统不上传发票文件，只保存哈希和链下编号元数据。

### 3.2 发起融资并接受报价

1. Buyer 确认后，切回 Supplier。
2. 在 `Activity → Financing` 找到对应发票，点击 `Request financing`。
3. 填写 principal、maximum rate、holdback 和 deadline，确认交易。
4. Funder 报价后刷新数据，查看报价并点击 `Accept`。

接受报价不等于已经放款；还需等待被选中的 Funder 执行 `Fund`。

## 4. Buyer 操作

### 4.1 确认发票

1. 第一次操作时用 Buyer 钱包连接并 `Sign in`，以便看到发票编号。
2. 进入 `Activity → Invoices`。
3. 核对 Supplier、Invoice number、Face value 和日期。
4. 点击 `Confirm`；若不同意则点击 `Reject`。

### 4.2 还款

在 `Activity → Financing` 找到已放款记录，点击 `Repay`，核对 MetaMask 中附带的测试 ETH 金额后确认。

- 没有争议时，交易直接完成结算。
- 存在未解决争议时，资金进入合约托管，状态变为 `Repayment deposited`，不要重复还款。

## 5. Funder 操作

1. 进入 `Activity → Financing`，在可用请求中选择融资。
2. 点击 `Submit offer`，填写利率并确认交易。
3. 报价被 Supplier 接受后，点击 `Fund`。
4. 在 MetaMask 中确认附带的本金金额；放款后可以查看 principal、holdback、Supplier upfront 和利息。

报价被接受前可以撤回。若到达相应时间条件，界面还会显示过期、逾期或违约动作。

## 6. 争议与 Arbitrator

### 6.1 发起争议和提交证据

Supplier、Buyer 或本次 Funder 可在符合条件的发票上进入 `Activity → Disputes`：

1. 点击打开争议，输入简短原因，例如 `Buyer disputes delivery quality`。
2. 前端会把文字计算成 Keccak-256 哈希，再调用 `openDispute`；链上不保存原文。
3. 需要追加证据时，输入说明并点击提交；前端同样只提交 evidence hash。

也可以直接输入合法的 `0x` 开头、共 66 个字符的 `bytes32` 哈希。演示不需要准备真实文件，使用一段易解释的文字即可。

### 6.2 Arbitrator 查看和裁决

1. 切换到具有 Arbitrator 权限的钱包和角色。
2. 进入 `Activity → Disputes`，打开对应案件。
3. 查看 reason hash、evidence hash、提交人、时间和当前业务阶段。
4. 根据页面提供的选项裁决：

   - `Resume`：解除冻结并继续原流程；
   - `Cancel`：融资开放、尚未放款时取消；
   - `Confirm default`：已放款或逾期时确认违约。

Arbitrator 只能看到链上哈希，不能读取原始文字或文件。六分钟演示中建议在争议未解决时让 Buyer 还款，展示 `Repayment deposited` 托管状态，再由 Arbitrator 选择 `Resume` 完成结算。

## 7. Auditor 操作

1. 用已激活 Auditor 的钱包连接并 `Sign in`，这样可以读取所有发票编号元数据。
2. 切换到 `Auditor`，进入 `Activity → Audit`。
3. 查看 Overview、Cash flow 和 Event timeline。
4. 按类别或关键词筛选事件，点击交易哈希可在 Etherscan 核对。

Audit 数据由浏览器实时从五个合约读取，没有后端镜像。首次进入可能需要等待 RPC 扫描；正式演示前先打开一次 Audit 页面预热，并保持稳定的 Sepolia RPC。

## 8. 常见问题

| 情况 | 处理方式 |
|---|---|
| 看不到 Invoice number | 确认当前钱包已登录且有 Supplier、指定 Buyer、Funder、Arbitrator、Auditor 或 Admin 权限，然后刷新 |
| 角色旁是红点 | 该钱包未激活此角色，进入 `Profile → Manage` 申请并由 Admin 批准 |
| `Switch to Sepolia` | 在 MetaMask 切换到 Sepolia 后重试 |
| 钱包拒绝签名 | 没有交易上链；重新点击操作即可 |
| 交易已确认但页面未更新 | 等待数秒后刷新；先用 Etherscan 核对交易，避免重复付款 |
| Audit 加载较慢 | 等待实时日志扫描完成；检查 RPC 和网络，不要重复提交业务交易 |
| 证据为何只有哈希 | 当前版本只实现链上哈希存证，没有文件存储或原文恢复 |

完整六分钟演示顺序见[最短业务链测试操作流程](最短业务链测试操作流程.md)。
